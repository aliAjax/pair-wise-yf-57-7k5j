# pair-wise-yf-57 野外巡护离线调查应用

## 源提示词摘要
巡护员离线记录观察、轨迹点、样本编号、风险等级和现场情况，回到有网络环境后同步给站点负责人。负责人复核重复观察、位置异常、证据缺失和能力范围外事项；多人修改同一记录时保留版本并允许合并，应用需要适配手机屏幕、电量、弱网和后台恢复。

## 本轮实现：坐标对账（样线 / 轨迹点 / 观察记录）

手机轨迹点用 **GCJ-02**，站里样线和观察记录用 **WGS-84**。上传时**保留原始读数**，先统一换算为站点坐标（站心局部网格），再按样线带宽判定归属，从根上解决“回驻地同步把观察归错样线”。

规则落地（纯函数 + Redux reducer，均有测试）：

- **上传保留原始读数**：`rawLng/rawLat/crs` 永不覆写；换算结果单列 `site/datumId/transectId/distanceM`。
- **先换算后归属**：GCJ-02→WGS-84（标准火星坐标互转）→ 站点网格 → 点到样线折线距离，带宽内最近样线为归属，超出则未归线。
- **基准一变**：切换站点基准（网格原点/平移）时，未归档记录全部失效重算；**已归档记录锁定原结论**（`archivedTransectId`）。
- **样线归属一变**：该观察的负责人复核由「已复核」变「复核失效·待处理」，关联样本核验同步失效退回待处理；归属未变不扰动已完成结论；首次判线不算变更。
- **重复回传只入账一次**：去重键（观察=时间+原始读数+笔记；轨迹点=id+时间+读数），服务器已入账或队列在途均幂等跳过。
- **失败后接着重试**：同步失败的作业保留 `failed` 和 attempts，不丢队；恢复网络/点“失败重试”继续上传（界面可注入一次失败演示弱网）。
- **旧记录缺坐标系**：`crs=null` 的旧记录按设备默认坐标系补齐（标记 `crsInferred`）再重判；设备默认变更时，所有待补齐记录按新默认重新判定。

### 代码结构
- `src/domain/geo.ts` — GCJ-02/WGS-84 互转、站点网格投影、点线距离与归属。
- `src/domain/reconcile.ts` — 对账规则：换算、归属变化、级联失效、基准全量重算、旧记录补齐。
- `src/domain/sync.ts` — 同步队列：去重入账一次、失败保留与重试。
- `src/domain/types.ts` / `seed.ts` — 领域模型与可复现演示数据（d2 基准平移会让 o2 从 T1 翻到 T2）。
- `src/store/patrolSlice.ts` — Redux 接线（含旧版本本地状态迁移）。
- `src/platform/storage.ts` — Taro 存储适配，Node 测试下退化为内存存储。
- `tests/` — 13 个单元/端到端测试（`npm test`）。

## 技术栈
Taro 3 + React + TypeScript + NutUI + Redux Toolkit + React Hook Form + Taro 国际化方案。

## 已实现闭环
- 观察记录、轨迹点、样本三类业务对象，均带原始读数、站点坐标与样线归属。
- 基准/设备默认坐标系切换、样线编辑后的自动重算与级联失效；归档锁定。
- 离线队列、弱网失败重试、重复回传幂等。
- Taro 本地存储持久化（含旧数据迁移）和移动端布局。
